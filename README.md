# BookHub

## Индивидуальная работа по PHP

**Тема проекта:** разработка традиционного веб-приложения средней сложности с функционалом на стороне сервера.

**Название проекта:** `BookHub`

**Описание:**  
`BookHub` — это веб-приложение для просмотра и управления каталогом книг.  
В проекте реализованы регистрация пользователей, вход в систему, роли пользователей, публичный каталог книг, поиск, добавление книг и административная панель.

Таблица users

Таблица users хранит данные пользователей.

CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) NOT NULL UNIQUE,
    email VARCHAR(100) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,
    role ENUM('user', 'admin') NOT NULL DEFAULT 'user',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
Поля таблицы users
Поле	Тип	Описание
id	INT	Уникальный идентификатор пользователя
username	VARCHAR(50)	Имя пользователя

password	VARCHAR(255)	Хешированный пароль

created_at	TIMESTAMP	Дата создания аккаунта
Таблица genres

Таблица genres хранит жанры книг.

CREATE TABLE genres (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL UNIQUE

Поля таблицы genres
Поле	Тип	Описание

name	VARCHAR(100)	Название жанра
Таблица books

Таблица books хранит информацию о книгах.

CREATE TABLE books (
    id INT AUTO_INCREMENT PRIMARY KEY,
    title VARCHAR(150) NOT NULL,
    author VARCHAR(100) NOT NULL,
    genre_id INT NOT NULL,
    year INT NOT NULL,
    description TEXT NOT NULL,
    status ENUM('available', 'unavailable') NOT NULL DEFAULT 'available',
    user_id INT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

    FOREIGN KEY (genre_id) REFERENCES genres(id) ON DELETE RESTRICT,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE SET NULL
);
Поля таблицы books
Поле	Тип	Описание
id	INT	Уникальный идентификатор книги
title	VARCHAR(150)	Название книги
author	VARCHAR(100)	Автор книги
genre_id	INT	Внешний ключ на таблицу жанров
year	INT	Год издания
description	TEXT	Описание книги
status	ENUM	Статус книги
user_id	INT	Пользователь, который добавил книгу
created_at	TIMESTAMP	Дата добавления книги

Безопасность проекта

В проекте реализованы основные требования безопасности.

1. Хеширование паролей

Пароли не хранятся в базе данных в открытом виде.

Для создания хеша используется:

password_hash($password, PASSWORD_DEFAULT);

Для проверки пароля используется:

password_verify($password, $user['password']);
2. Защита от SQL-инъекций

Для работы с базой данных используется PDO и подготовленные запросы.

Пример:

$stmt = $pdo->prepare("SELECT * FROM users WHERE email = :email LIMIT 1");
$stmt->execute([':email' => $email]);

Такой способ защищает приложение от SQL-инъекций.

3. Защита от XSS

Для безопасного вывода данных используется функция htmlspecialchars().

В проекте создана вспомогательная функция:

function e(?string $value): string
{
    return htmlspecialchars($value ?? '', ENT_QUOTES, 'UTF-8');
}

Она используется при выводе данных на страницу:

<?= e($book['title']) ?>
4. Защита закрытых страниц

Для защиты закрытых страниц используется сессия.

Если пользователь не вошёл в систему, он перенаправляется на страницу входа.

function requireAuth(): void
{
    if (!isLoggedIn()) {
        redirect('/bookhub/public/login.php');
    }
}
5. Проверка роли администратора

Для доступа к админ-панели проверяется роль пользователя.

function requireAdmin(): void
{
    requireAuth();

    if (!isAdmin()) {
        redirect('/bookhub/public/index.php');
    }
}
6. Валидация данных

В проекте используется два типа проверки:

клиентская проверка;
серверная проверка.

Клиентская проверка выполняется с помощью HTML и JavaScript.

Пример HTML-проверки:

<input type="text" name="title" required minlength="2" maxlength="150">

Серверная проверка выполняется в PHP.

Пример:

if (strlen($title) < 2 || strlen($title) > 150) {
    $errors[] = 'Название книги должно содержать от 2 до 150 символов.';
}
Ответы на контрольные вопросы
1. Что такое традиционное веб-приложение?

Традиционное веб-приложение — это приложение, где страницы формируются на сервере.
Пользователь отправляет запрос, сервер обрабатывает его, получает данные из базы данных и возвращает готовую HTML-страницу.

В проекте BookHub страницы создаются с помощью PHP.

2. Для чего используется PHP?

PHP используется для серверной логики приложения.

В проекте PHP отвечает за:

регистрацию пользователей;
вход в систему;
работу с сессиями;
подключение к базе данных;
добавление книг;
поиск книг;
редактирование данных;
удаление данных;
проверку прав доступа.
3. Что такое база данных?

База данных — это система хранения информации в структурированном виде.

В проекте база данных хранит:

пользователей;
жанры книг;
книги.
4. Для чего используется MySQL?

MySQL используется для хранения данных проекта.

Например, в MySQL сохраняются:

email пользователя;
хеш пароля;
роль пользователя;
названия книг;
авторы;
жанры;
описания книг.
5. Что такое PDO?

PDO — это способ подключения PHP к базе данных.

PDO позволяет выполнять SQL-запросы и использовать подготовленные выражения.

Пример:

$pdo = new PDO(
    "mysql:host={$host};dbname={$databaseName};charset=utf8mb4",
    $username,
    $password
);
6. Что такое SQL-инъекция?

SQL-инъекция — это атака, при которой злоумышленник пытается вставить вредоносный SQL-код в форму сайта.

Например, если не использовать защиту, пользователь может ввести в поле формы часть SQL-запроса и повредить данные.

7. Как защититься от SQL-инъекции?

Для защиты от SQL-инъекций нужно использовать подготовленные запросы.

Пример:

$stmt = $pdo->prepare("SELECT * FROM users WHERE email = :email");
$stmt->execute([':email' => $email]);

В этом случае данные пользователя не вставляются напрямую в SQL-запрос.

8. Почему нельзя хранить пароли в открытом виде?

Пароли нельзя хранить в открытом виде, потому что при взломе базы данных злоумышленник сразу увидит настоящие пароли пользователей.

Поэтому пароль нужно хешировать.

9. Что делает функция password_hash()?

Функция password_hash() создаёт безопасный хеш пароля.

Пример:

$hashedPassword = password_hash($password, PASSWORD_DEFAULT);

В базе данных хранится не сам пароль, а его хеш.

10. Что делает функция password_verify()?

Функция password_verify() проверяет, соответствует ли введённый пароль хешу из базы данных.

Пример:

password_verify($password, $user['password']);

Если пароль правильный, функция возвращает true.

11. Что такое сессия?

Сессия — это механизм хранения данных о пользователе между страницами сайта.

В проекте в сессии хранятся:

$_SESSION['user_id'];
$_SESSION['username'];
$_SESSION['role'];

Это позволяет сайту понимать, какой пользователь вошёл в систему.

12. Для чего используется session_start()?

session_start() запускает сессию на странице.

Без этой функции PHP не сможет работать с массивом $_SESSION.

13. Что такое авторизация?

Авторизация — это проверка прав пользователя.

Например, обычный пользователь может добавлять книги, но не может открывать админ-панель.

Администратор имеет больше прав.

14. Что такое аутентификация?

Аутентификация — это проверка личности пользователя.

В проекте пользователь вводит email и пароль.
Если данные правильные, он входит в систему.

15. Чем аутентификация отличается от авторизации?

Аутентификация отвечает на вопрос:

Кто ты?

Авторизация отвечает на вопрос:

Что тебе разрешено делать?

Например:

вход по email и паролю — это аутентификация;
проверка роли admin — это авторизация.
16. Что такое роль пользователя?

Роль пользователя определяет его права в системе.

В проекте есть две роли:

user
admin

Пользователь с ролью admin имеет доступ к административной панели.

17. Для чего нужна валидация данных?

Валидация нужна для проверки данных, которые пользователь вводит в формы.

Например, нужно проверить:

заполнено ли поле;
корректный ли email;
достаточная ли длина пароля;
корректный ли год издания книги.
18. Почему нужна проверка и на клиенте, и на сервере?

Клиентская проверка удобна для пользователя, потому что сразу показывает ошибку в браузере.

Но её можно обойти.
Поэтому главная проверка обязательно должна быть на сервере.

В проекте используются оба варианта проверки.

19. Что такое XSS?

XSS — это атака, при которой злоумышленник вставляет вредоносный JavaScript-код на страницу сайта.

Например, пользователь может попытаться добавить в название книги тег <script>.

20. Как защититься от XSS?

Для защиты от XSS нужно экранировать данные перед выводом на страницу.

В проекте используется функция:

htmlspecialchars();
21. Что такое CRUD?

CRUD — это основные операции с данными:

Create — создание;
Read — чтение;
Update — обновление;
Delete — удаление.

В проекте CRUD реализован для книг.

22. Что такое модульная архитектура?

Модульная архитектура — это разделение проекта на отдельные части.

В проекте отдельно находятся:

настройки базы данных;
публичные страницы;
админ-панель;

стили;
скрипты.

Такой подход делает проект удобнее для поддержки и расширения.

23. Для чего используется PHPDoc?

PHPDoc используется для документирования функций и методов.

Пример:

/**
 * Проверяет, является ли текущий пользователь авторизованным.
 *
 * @return bool true, если пользователь вошёл в систему.
 */
function isLoggedIn(): bool
{
    return isset($_SESSION['user_id']);
}

Такие комментарии помогают понять назначение функции.

24. Для чего используется htmlspecialchars()?

htmlspecialchars() преобразует специальные символы в безопасный HTML-вид.

Например:

<script>

будет выведено как обычный текст, а не выполнится как код.

25. Для чего используется redirect()?

Функция redirect() перенаправляет пользователя на другую страницу.

Пример:

redirect('/bookhub/public/login.php');

В проекте она используется после входа, выхода, добавления книги и при запрете доступа.
