# BookHub

BookHub — это традиционное веб-приложение средней сложности на PHP и MySQL.  
Проект разработан для индивидуальной работы по PHP.

## Описание лабораторной работы

Цель работы — разработать веб-приложение с серверной логикой, регистрацией пользователей, авторизацией, ролями, публичным каталогом, формами взаимодействия и защищённой административной частью.

## Функциональные возможности

- Регистрация пользователей
- Вход и выход из системы
- Хранение паролей в хешированном виде
- Управление доступом через `$_SESSION`
- Публичная главная страница
- Публичный каталог книг
- Просмотр подробной информации о книге
- Форма добавления книги
- Форма поиска книг
- Клиентская и серверная валидация форм
- Роль администратора
- Создание новых администраторов
- Просмотр пользователей
- Просмотр, редактирование и удаление книг

## Инструкция по запуску

1. Установить локальный сервер, например XAMPP.
2. Скопировать папку `bookhub` в папку `htdocs`.
3. Открыть phpMyAdmin.
4. Импортировать файл `database.sql`.
5. Проверить настройки подключения в файле:

```php
config/database.php
```

6. Открыть сайт в браузере:

```text
http://localhost/bookhub/public/index.php
```

## Сценарии взаимодействия пользователей

### Гость

1. Открывает главную страницу.
2. Просматривает последние книги.
3. Переходит в каталог.
4. Использует поиск.
5. Может зарегистрироваться или войти в систему.

### Обычный пользователь

1. Входит в систему.
2. Получает доступ к защищённым страницам.
3. Добавляет новую книгу.
4. Может редактировать и удалять свои книги.

### Администратор

1. Входит в систему.
2. Открывает админ-панель.
3. Просматривает всех пользователей.
4. Создаёт новых администраторов.
5. Управляет всеми книгами: просматривает, редактирует, удаляет.

## Безопасность

В проекте используются следующие меры безопасности:

- `password_hash()` для хеширования паролей.
- `password_verify()` для проверки паролей.
- PDO и подготовленные запросы для защиты от SQL-инъекций.
- `htmlspecialchars()` для защиты от XSS.
- `$_SESSION` для управления доступом.
- Проверка роли администратора.
- Клиентская и серверная валидация данных.

## Контрольные вопросы

### 1. Почему пароли нельзя хранить в открытом виде?

Пароли нельзя хранить в открытом виде, потому что при утечке базы данных злоумышленник сразу получит доступ к аккаунтам пользователей.

### 2. Для чего используется `password_hash()`?

`password_hash()` создаёт безопасный хеш пароля, который можно хранить в базе данных.

### 3. Для чего используется `password_verify()`?

`password_verify()` сравнивает введённый пароль с хешем из базы данных.

### 4. Что такое SQL-инъекция?

SQL-инъекция — это атака, при которой злоумышленник пытается вставить вредоносный SQL-код в поля формы.

### 5. Как защититься от SQL-инъекции?

Нужно использовать подготовленные запросы, например PDO `prepare()` и `execute()`.

### 6. Для чего нужны сессии?

Сессии нужны для хранения информации о пользователе после входа в систему.

### 7. Что делает администратор?

Администратор управляет пользователями и данными в базе данных.
