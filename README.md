# BookHub

## Индивидуальная работа по PHP

**Тема проекта:** разработка традиционного веб-приложения средней сложности с функционалом на стороне сервера.

**Название проекта:** `BookHub`

**Описание проекта:**  
`BookHub` — это веб-приложение для просмотра и управления каталогом книг. В проекте реализованы регистрация пользователей, вход в систему, роли пользователей, публичный каталог книг, поиск, добавление книг и административная панель.

## Инструкции по запуску проекта

### 1. Установка локального сервера

Для запуска проекта используется локальный сервер `XAMPP`.

Необходимо запустить следующие модули:

- `Apache`
- `MySQL`

---

### 2. Размещение проекта

Папку проекта необходимо скопировать в директорию:

```text
C:\xampp\htdocs
```

Итоговый путь к проекту должен быть таким:

```text
C:\xampp\htdocs\bookhub
```

---

### 3. Импорт базы данных

Для работы проекта нужно импортировать базу данных.

Порядок действий:

1. Открыть браузер.
2. Перейти по адресу:

```text
http://localhost/phpmyadmin
```

3. Создать базу данных с названием:

```text
bookhub
```

4. Открыть вкладку `Import`.
5. Выбрать файл:

```text
database.sql
```

6. Нажать кнопку `Go`.

После этого будут созданы таблицы `users`, `genres` и `books`.

---

### 4. Настройка подключения к базе данных

Файл подключения к базе данных находится по пути:

```text
config/database.php
```

Пример настроек подключения:

```php
$host = 'localhost';
$databaseName = 'bookhub';
$username = 'root';
$password = '';
```

Для стандартного XAMPP пользователь базы данных — `root`, а пароль обычно пустой.

---

### 5. Запуск проекта

После запуска `Apache` и `MySQL` нужно открыть сайт в браузере:

```text
http://localhost/bookhub/public/index.php
```

---

### 6. Данные администратора

Для входа в административную панель используется аккаунт администратора:

```text
Email: admin@example.com
Password: admin123
```

Проект состоит из нескольких основных частей:

- публичная часть сайта;
- система регистрации;
- система входа в аккаунт;
- защищённая часть для авторизованных пользователей;
- административная панель;
- база данных MySQL;
- клиентская и серверная валидация форм.

## Функциональные возможности

### 1. Регистрация пользователей

Пользователь может создать новый аккаунт.

Форма регистрации содержит:

- имя пользователя;
- email;
- пароль;
- повтор пароля.

Пароль не сохраняется в базе данных в открытом виде. Для его защиты используется функция:

```php
password_hash($password, PASSWORD_DEFAULT);
```

---

### 2. Вход в систему

Пользователь может войти в систему по email и паролю.

Проверка пароля выполняется с помощью функции:

```php
password_verify($password, $user['password']);
```

После успешного входа данные пользователя сохраняются в сессии:

```php
$_SESSION['user_id'] = $user['id'];
$_SESSION['username'] = $user['username'];
$_SESSION['role'] = $user['role'];
```

---

### 3. Выход из системы

Пользователь может выйти из аккаунта.

При выходе данные сессии очищаются:

```php
$_SESSION = [];
session_destroy();
```

---

### 4. Публичная главная страница

Главная страница доступна всем пользователям без авторизации.

На ней отображаются последние добавленные книги из базы данных.

Пример SQL-запроса:

```php
$stmt = $pdo->query(
    "SELECT books.*, genres.name AS genre_name
     FROM books
     JOIN genres ON books.genre_id = genres.id
     ORDER BY books.created_at DESC"
);
```

---

### 5. Каталог книг

На странице каталога отображаются все книги, которые находятся в базе данных.

Для каждой книги выводится:

- название;
- автор;
- жанр;
- год издания;
- статус;
- кнопка для просмотра подробной информации.

---

### 6. Просмотр подробной информации о книге

Пользователь может открыть отдельную страницу книги.

На странице отображаются:

- название книги;
- автор;
- жанр;
- год издания;
- статус;
- пользователь, который добавил книгу;
- полное описание книги.

---

### 7. Добавление книги

Авторизованный пользователь может добавить новую книгу.

Форма добавления книги содержит следующие поля:

- название книги;
- автор;
- жанр;
- год издания;
- описание;
- статус.

Форма содержит больше 5 полей разных типов:

- текстовые поля;
- числовое поле;
- выпадающий список;
- поле `textarea`;
- кнопка отправки формы.

---

### 8. Поиск книг

В проекте реализована форма поиска.

Пользователь может искать книги:

- по названию;
- по автору;
- по жанру.

Пример фрагмента SQL-запроса для поиска:

```php
$sql = "SELECT books.*, genres.name AS genre_name
        FROM books
        JOIN genres ON books.genre_id = genres.id
        WHERE 1=1";

if ($query !== '') {
    $sql .= " AND (books.title LIKE :query OR books.author LIKE :query)";
    $params[':query'] = '%' . $query . '%';
}

if ($genreId !== '') {
    $sql .= " AND books.genre_id = :genre_id";
    $params[':genre_id'] = (int)$genreId;
}
```

---

### 9. Защищённые страницы

Некоторые страницы доступны только после входа в систему.

Например:

- добавление книги;
- редактирование книги;
- удаление книги;
- административная панель.

Проверка авторизации выполняется через функцию `requireAuth()`.

```php
function requireAuth(): void
{
    if (!isLoggedIn()) {
        redirect('/bookhub/public/login.php');
    }
}
```

---

### 10. Роль администратора

В проекте есть две роли пользователей:

- `user` — обычный пользователь;
- `admin` — администратор.

Роль хранится в таблице `users` в поле `role`.

Администратор имеет дополнительные возможности:

- просмотр всех пользователей;
- создание новых администраторов;
- просмотр всех книг;
- добавление книг;
- редактирование любых книг;
- удаление любых книг;
- доступ к административной панели.

Проверка администратора выполняется через функцию `requireAdmin()`.

```php
function requireAdmin(): void
{
    requireAuth();

    if (!isAdmin()) {
        redirect('/bookhub/public/index.php');
    }
}
```

## Структура базы данных

В проекте используется база данных MySQL с названием:

```text
bookhub
```

База данных состоит из трёх основных таблиц:

- `users`
- `genres`
- `books`

---

### Таблица `users`

Таблица `users` хранит данные пользователей.

```sql
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) NOT NULL UNIQUE,
    email VARCHAR(100) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,
    role ENUM('user', 'admin') NOT NULL DEFAULT 'user',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### Поля таблицы `users`

| Поле | Тип | Описание |
|---|---|---|
| `id` | `INT` | Уникальный идентификатор пользователя |
| `username` | `VARCHAR(50)` | Имя пользователя |
| `email` | `VARCHAR(100)` | Email пользователя |
| `password` | `VARCHAR(255)` | Хешированный пароль |
| `role` | `ENUM('user', 'admin')` | Роль пользователя |
| `created_at` | `TIMESTAMP` | Дата создания аккаунта |

---

### Таблица `genres`

Таблица `genres` хранит жанры книг.

```sql
CREATE TABLE genres (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL UNIQUE
);
```

#### Поля таблицы `genres`

| Поле | Тип | Описание |
|---|---|---|
| `id` | `INT` | Уникальный идентификатор жанра |
| `name` | `VARCHAR(100)` | Название жанра |

---

### Таблица `books`

Таблица `books` хранит информацию о книгах.

```sql
CREATE TABLE books (
    id INT AUTO_INCREMENT PRIMARY KEY,
    title VARCHAR(150) NOT NULL,
    author VARCHAR(100) NOT NULL,
    genre_id INT NOT NULL,
    year INT NOT NULL,
    description TEXT NOT NULL,
    status ENUM('available', 'unavailable') NOT NULL DEFAULT 'available',
    user_id INT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

    FOREIGN KEY (genre_id) REFERENCES genres(id) ON DELETE RESTRICT,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE SET NULL
);
```

#### Поля таблицы `books`

| Поле | Тип | Описание |
|---|---|---|
| `id` | `INT` | Уникальный идентификатор книги |
| `title` | `VARCHAR(150)` | Название книги |
| `author` | `VARCHAR(100)` | Автор книги |
| `genre_id` | `INT` | Внешний ключ на таблицу жанров |
| `year` | `INT` | Год издания |
| `description` | `TEXT` | Описание книги |
| `status` | `ENUM('available', 'unavailable')` | Статус книги |
| `user_id` | `INT` | Пользователь, который добавил книгу |
| `created_at` | `TIMESTAMP` | Дата добавления книги |

---

### Связи между таблицами

#### Связь `genres` → `books`

Один жанр может относиться ко многим книгам.

Тип связи:

```text
1 ко многим
```

Пример:

```text
Один жанр "Фантастика" может быть у многих книг.
```

---

#### Связь `users` → `books`

Один пользователь может добавить много книг.

Тип связи:

```text
1 ко многим
```

Пример:

```text
Один пользователь может добавить несколько книг в каталог.
```

## Безопасность проекта

В проекте реализованы основные требования безопасности.

---

### 1. Хеширование паролей

Пароли не хранятся в базе данных в открытом виде.

Для создания хеша используется:

```php
password_hash($password, PASSWORD_DEFAULT);
```

Для проверки пароля используется:

```php
password_verify($password, $user['password']);
```

---

### 2. Защита от SQL-инъекций

Для работы с базой данных используется PDO и подготовленные запросы.

Пример:

```php
$stmt = $pdo->prepare("SELECT * FROM users WHERE email = :email LIMIT 1");
$stmt->execute([':email' => $email]);
```

Такой способ защищает приложение от SQL-инъекций.

---

### 3. Защита от XSS

Для безопасного вывода данных используется функция `htmlspecialchars()`.

В проекте создана вспомогательная функция:

```php
function e(?string $value): string
{
    return htmlspecialchars($value ?? '', ENT_QUOTES, 'UTF-8');
}
```

Она используется при выводе данных на страницу:

```php
<?= e($book['title']) ?>
```

---

### 4. Защита закрытых страниц

Для защиты закрытых страниц используется сессия.

Если пользователь не вошёл в систему, он перенаправляется на страницу входа.

```php
function requireAuth(): void
{
    if (!isLoggedIn()) {
        redirect('/bookhub/public/login.php');
    }
}
```

---

### 5. Проверка роли администратора

Для доступа к админ-панели проверяется роль пользователя.

```php
function requireAdmin(): void
{
    requireAuth();

    if (!isAdmin()) {
        redirect('/bookhub/public/index.php');
    }
}
```

---

### 6. Валидация данных

В проекте используется два типа проверки:

- клиентская проверка;
- серверная проверка.

Клиентская проверка выполняется с помощью HTML и JavaScript.

Пример HTML-проверки:

```html
<input type="text" name="title" required minlength="2" maxlength="150">
```

Серверная проверка выполняется в PHP.

Пример:

```php
if (strlen($title) < 2 || strlen($title) > 150) {
    $errors[] = 'Название книги должно содержать от 2 до 150 символов.';
}
```

## Ответы на контрольные вопросы

### 1. Что такое традиционное веб-приложение?

Традиционное веб-приложение — это приложение, где страницы формируются на сервере. Пользователь отправляет запрос, сервер обрабатывает его, получает данные из базы данных и возвращает готовую HTML-страницу.

В проекте `BookHub` страницы создаются с помощью PHP.

---

### 2. Для чего используется PHP?

PHP используется для серверной логики приложения.

В проекте PHP отвечает за:

- регистрацию пользователей;
- вход в систему;
- работу с сессиями;
- подключение к базе данных;
- добавление книг;
- поиск книг;
- редактирование данных;
- удаление данных;
- проверку прав доступа.

---

### 3. Что такое база данных?

База данных — это система хранения информации в структурированном виде.

В проекте база данных хранит:

- пользователей;
- жанры книг;
- книги.

---

### 4. Для чего используется MySQL?

MySQL используется для хранения данных проекта.

Например, в MySQL сохраняются:

- email пользователя;
- хеш пароля;
- роль пользователя;
- названия книг;
- авторы;
- жанры;
- описания книг.

---

### 5. Что такое PDO?

PDO — это способ подключения PHP к базе данных.

PDO позволяет выполнять SQL-запросы и использовать подготовленные выражения.

Пример подключения:

```php
$pdo = new PDO(
    "mysql:host={$host};dbname={$databaseName};charset=utf8mb4",
    $username,
    $password
);
```

---

### 6. Что такое SQL-инъекция?

SQL-инъекция — это атака, при которой злоумышленник пытается вставить вредоносный SQL-код в форму сайта.

Например, если не использовать защиту, пользователь может ввести в поле формы часть SQL-запроса и повредить данные.

---

### 7. Как защититься от SQL-инъекции?

Для защиты от SQL-инъекций нужно использовать подготовленные запросы.

Пример:

```php
$stmt = $pdo->prepare("SELECT * FROM users WHERE email = :email");
$stmt->execute([':email' => $email]);
```

В этом случае данные пользователя не вставляются напрямую в SQL-запрос.

---

### 8. Почему нельзя хранить пароли в открытом виде?

Пароли нельзя хранить в открытом виде, потому что при взломе базы данных злоумышленник сразу увидит настоящие пароли пользователей.

Поэтому пароль нужно хешировать.

---

### 9. Что делает функция `password_hash()`?

Функция `password_hash()` создаёт безопасный хеш пароля.

Пример:

```php
$hashedPassword = password_hash($password, PASSWORD_DEFAULT);
```

В базе данных хранится не сам пароль, а его хеш.

---

### 10. Что делает функция `password_verify()`?

Функция `password_verify()` проверяет, соответствует ли введённый пароль хешу из базы данных.

Пример:

```php
password_verify($password, $user['password']);
```

Если пароль правильный, функция возвращает `true`.

---

### 11. Что такое сессия?

Сессия — это механизм хранения данных о пользователе между страницами сайта.

В проекте в сессии хранятся:

```php
$_SESSION['user_id'];
$_SESSION['username'];
$_SESSION['role'];
```

Это позволяет сайту понимать, какой пользователь вошёл в систему.

---

### 12. Для чего используется `session_start()`?

`session_start()` запускает сессию на странице.

Без этой функции PHP не сможет работать с массивом `$_SESSION`.

---

### 13. Что такое авторизация?

Авторизация — это проверка прав пользователя.

Например, обычный пользователь может добавлять книги, но не может открывать админ-панель.

Администратор имеет больше прав.

---

### 14. Что такое аутентификация?

Аутентификация — это проверка личности пользователя.

В проекте пользователь вводит email и пароль. Если данные правильные, он входит в систему.

---

### 15. Чем аутентификация отличается от авторизации?

Аутентификация отвечает на вопрос:

```text
Кто ты?
```

Авторизация отвечает на вопрос:

```text
Что тебе разрешено делать?
```

Например:

- вход по email и паролю — это аутентификация;
- проверка роли `admin` — это авторизация.

---

### 16. Что такое роль пользователя?

Роль пользователя определяет его права в системе.

В проекте есть две роли:

```text
user
admin
```

Пользователь с ролью `admin` имеет доступ к административной панели.

---

### 17. Для чего нужна валидация данных?

Валидация нужна для проверки данных, которые пользователь вводит в формы.

Например, нужно проверить:

- заполнено ли поле;
- корректный ли email;
- достаточная ли длина пароля;
- корректный ли год издания книги.

---

### 18. Почему нужна проверка и на клиенте, и на сервере?

Клиентская проверка удобна для пользователя, потому что сразу показывает ошибку в браузере.

Но её можно обойти. Поэтому главная проверка обязательно должна быть на сервере.

В проекте используются оба варианта проверки.

---

### 19. Что такое XSS?

XSS — это атака, при которой злоумышленник вставляет вредоносный JavaScript-код на страницу сайта.

Например, пользователь может попытаться добавить в название книги тег `<script>`.

---

### 20. Как защититься от XSS?

Для защиты от XSS нужно экранировать данные перед выводом на страницу.

В проекте используется функция:

```php
htmlspecialchars();
```

---

### 21. Что такое CRUD?

CRUD — это основные операции с данными:

- `Create` — создание;
- `Read` — чтение;
- `Update` — обновление;
- `Delete` — удаление.

В проекте CRUD реализован для книг.

---

### 22. Что такое модульная архитектура?

Модульная архитектура — это разделение проекта на отдельные части.

В проекте отдельно находятся:

- настройки базы данных;
- публичные страницы;
- админ-панель;
- работа с книгами;
- общие файлы;
- стили;
- скрипты.

Такой подход делает проект удобнее для поддержки и расширения.

---

### 23. Для чего используется PHPDoc?

PHPDoc используется для документирования функций и методов.

Пример:

```php
/**
 * Проверяет, является ли текущий пользователь авторизованным.
 *
 * @return bool true, если пользователь вошёл в систему.
 */
function isLoggedIn(): bool
{
    return isset($_SESSION['user_id']);
}
```

Такие комментарии помогают понять назначение функции.

---

### 24. Для чего используется `htmlspecialchars()`?

`htmlspecialchars()` преобразует специальные символы в безопасный HTML-вид.

Например, если пользователь введёт:

```html
<script>alert('test')</script>
```

то этот текст будет выведен как обычный текст, а не выполнится как JavaScript-код.

---

### 25. Для чего используется `redirect()`?

Функция `redirect()` перенаправляет пользователя на другую страницу.

Пример:

```php
redirect('/bookhub/public/login.php');
```

В проекте она используется после входа, выхода, добавления книги и при запрете доступа.
